# Random-data LeWM: matched PushObj evaluation

This evaluation is authorized to follow the eight-GPU random-data LeWM training.
It waits for `training_result.json`, including final checkpoint epoch 10 / step
127360, strict original-model loading, finite weights, and checkpoint SHA-256.
It does not evaluate partial checkpoints or change the ongoing training run.

## Protocol

- Seven shapes: I, L, square, Z, small_tee, plus, T; 50 identical paired tasks each.
- Two frozen-model arms: native GD planning and current ECP with contact optimization.
- 30 MPC replans × 5 environment controls = at most 150 controls per task.
- Horizon 25 environment controls; 100 GD iterations; same deterministic initialization
  and action warm starts as the archived augmented model evaluation.
- ECP: latent movement thresholds 0.15 / 0.45, start at replan 10, window 3,
  memory regularizer kappa 2 / beta 0.25, contact optimization weight 10,
  four-replan contact bursts, at most seven contact-guided replans, and the same
  conditional analytic proprioceptive guidance as the augmented reference.
- Contact targets use observed simulator object state and known shape geometry.
  The inherited 3–20 bias fields are inactive in the contact-objective planner:
  there is no post-optimization additive action offset in this condition.
- Up to eight GPU evaluation workers, only after the training supervisor verifies
  completion. Existing unrelated GPU processes are not stopped.

## Provenance and outputs

`inputs/` contains immutable copies of the seven task segments. `configs/` changes
only checkpoint, segment, and output paths from the archived augmented runs.
`reference_augmented/` preserves paired enhanced-model outcomes (native 215/350;
ECP 231/350). These archived outcomes are not rerun.

The source snapshot is tracked at
`reports/lewm_contact_schedule_20261113/lewm_ecp_045_contact_objective/source`.
`asset_manifest.json` records its file hashes plus all input/config hashes.
Compared with the archived native source, its only shared Python-file difference
is a GD objective dispatch hook that returns the same native loss unless ECP is enabled.

`status.json` reports the queue and evaluation state; `queue.log` and `logs/`
record execution. Each run saves frozen-weight checks, actual action sequences,
success flags, and target states. Independent physics replay must reproduce all
700 new outcomes. Replay saves every control-step state and contact indicator in
`full/<arm>/<shape>/replayed_trajectories.npz` for later trajectory visualizations.
No simulation screenshots are generated by this evaluation queue.

On successful completion: `RESULTS.md`, `results.json`, `per_shape.csv`, and
`paired_tasks.csv` compare random/augmented data with and without ECP.

The queue is started once as a detached process; `queue.lock` prevents concurrent
duplicates. Existing evaluation output directories are never silently overwritten.
