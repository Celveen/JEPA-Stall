# 切换参数与持续模型更新的验证

2026-11-02。用户授权验证统一参数、分环境校准和降低门槛的方案。本轮不修改世界模型、优化器、规划预算或代价修正强度。

## 问题与可检验主张

判断的是“何时叠加规划代价修正”。保留预测误差信号，但不把它解释为已经证明模型学不动或过拟合。50次重规划本身不能判断是否过拟合。所有主实验都显式设置 `switch.freeze=false`，切换之后模型仍按原 AdaJEPA 规则更新。

按“让模型多学一会”解释本次门槛调整：切换条件是近期误差下降比例小于 θ，因此 θ 从5%降至1%会减少过早切换。它改变的是开始代价修正的时机，不会停止模型更新。

| 组 | W | θ | K | 代价修正 | 模型更新 |
|---|---:|---:|---:|---|---|

另对照已有 AdaJEPA 和 R-trig。暂不同时改变停滞惩罚或本体权重，避免把修正方式的差异算到切换参数上。θ=0.01 的结果在固定这四组之后才回放，不根据结果追加搜索范围。

## 数据和预算

- 开发：迷宫 medium 种子100的100个任务；PushObj S7的280个任务。
- 每个新组重跑迷宫触发过的51个任务，PushObj第10次以前尚未成功的78个任务；保留任务原位置及随机种子。其余任务中修正不能生效，沿用基线结果。
- 3个新组，共387个任务×实验组，分60个作业。预算固定50次，同时报告20/30/50次。
- GPU由实际进程占用决定；避开已有任务的卡。每张卡最多两个迷宫作业。
- 首先每个新组、每个环境跑2个任务的冒烟测试，再运行正式开发实验。

## 判据与选择规则

主要指标是实际闭环成功率、配对救回/误伤和成功速度。F（及时覆盖失败任务）与S（在原本会成功前切换）只作辅助诊断，S不等于真实误伤。

统一与分环境选择都限于上面的四组。排序先看50次成功率，再看误伤更少，再看20/30次成功率更高；完全相同时按表中顺序取最先的。统一选择对两个环境等权，避免PushObj任务数更多而主导选择。开发集p值如实报告、注明未做多重比较校正，选出的最好结果不当成独立验证。

测试必须使用未参与本轮及此前开发的新任务/随机种子。已经多次查看的EVAL50不称为全新测试集。新的布局或形状泛化另行分开报告。参数和选择规则冻结后再测试；当前尚未产生独立测试结果。

## 运行与核对

在JEPA-Stall根目录、Python环境 `ts` 中运行：

```bash
python -B scripts/switch_calibration.py replay
python -B scripts/switch_calibration.py prepare
python -B scripts/switch_calibration.py run --smoke 2 --gpus 0,1,4,5,6,7 --jobs 6
python -B scripts/switch_calibration.py run --gpus 0,1,4,5,6,7 --jobs 6
```

GPU编号是原服务器常用值，实际运行前必须查询占用。脚本无CUDA时明确退出，不会偷偷在CPU上跑或把准备完成写成实验完成。

- 离线回放：用在线切换函数核对离线计算，共1520个任务×参数组合；0处不一致。PushObj旧轨迹的离线触发近似仍需要在线配对验证。
- 闭环：每个选中任务都必须有完整结束记录，切换之前的动作、成功状态和误差必须与基线一致，且模型更新未被配置为冻结。
- 更换硬件后若配对失败，先在相同硬件重跑对应基线，不将不匹配运行混在一起比较。
- 不完整任务、重复日志或未通过配对检查时，脚本拒绝生成总成功率。
- 冒烟和正式输出目录分开；不覆盖旧E3结果。
