# Wall 测试方案（v2）：基准按 DINO-WM，再把目前最好的方法原样搬过去

截至 2026-10-30。这只是方案，没有写代码，也没有跑实验；`wall_single` 数据正在下载。
- 你的要求（2026-10-30）：可以自己训模型，但基准要按 DINO-WM 来，训出来的模型不能比原文差很多。
- v1 是自己生成数据、用 SmallResNet、GD 规划，已作废：GD 规划在 Wall 上明显比原文的 CEM 差，见第 1 节。

## 0. 一句话

先在 DINO-WM 的 Wall 设定上，证明我们的评测和训练都能复现原文的水平（门槛），再在 DINO-WM 的 WallRandom（训练没见过的墙和门的位置）上测：
- 冻结规划器；
- AdaJEPA；
- 我们目前最好的方法：AdaJEPA，配合卡住触发、切换信号和 T0SP，即 R-switch，参数一个不调。

## 1. DINO-WM 的 Wall 设定和数字（查自原文 arXiv 2411.04983 和 DINO-WM 仓库）

| 项 | 值 |
|---|---|
| 数据 | 标准 Wall：1920 条轨迹 × 50 步，墙和门固定（墙 x = 32）；OSF 上公开为 `wall_single.zip`（1.67 GB） |
| WallRandom | 10240 条 × 50 步，墙和门的位置随机；测试时用和训练不重叠的墙/门位置。数据**没有公开**，要按原文做法自己生成 |
| 编码器 | 冻结的 DINOv2 ViT-S/14 patch 特征；frameskip 5；100 个 epoch，batch 32 |
| 评测 | 起点和目标随机放在墙两侧（`random_state`），50 个 episode，种子 99；成功 = 位置距离 < 4.5 |
| 规划器 | CEM（300 个样本，前 30，10 轮），地平线 5 个模型步；MPC 每次执行完整的 5 步再重规划 |
| 原文成功率 | 标准 Wall：开环 CEM 0.74，MPC 0.96；WallRandom：0.82（DreamerV3 0.76） |
| 公开权重 | OSF 上的 `outputs.zip`（0.95 GB），含 Wall |

另外两条参考：
- **原文和代码不一致的地方**：历史帧数（原文 1，代码 3），预测器学习率（原文 5e-5，代码 5e-4）。以 DINO-WM 公开权重里的 `hydra.yaml` 为准。
- **原文 MPC 的步数上限没写**：配置里 `max_iter` 是 null，代码会一直跑到全部成功为止。所以 0.96 用的步数上限不确定；开环 CEM 的 0.74 没有这个问题。
- **temporal-straightening 论文用 GD 规划的结果**：DINOv2 patch 在 Wall 上开环 53%、MPC 77%；从头训的 ResNet 开环 59%、MPC 68%。都明显低于原文的 CEM，所以 Wall 上要用 CEM。

## 2. 步骤

### G0 用 DINO-WM 的公开权重核对我们的评测

- **内容**：在我们的仓库里加载 DINO-WM 的 Wall 权重，按原文的设定跑开环 CEM 和 MPC。
- **步数上限**：MPC 用固定上限。上限先按原文的设定推算，跑出来报告。
- **目的**：确认我们的评测管线能复现 0.74 和 0.96。后面的门槛就是"我们的模型和 DINO-WM 的权重在同一套评测下比"，不受步数上限不确定的影响。
- **需要先解决的**：
  - 本机 Python 3.9 加载最新版 dinov2 会报错。办法是把 dinov2 固定到 2025-05-19 的版本（4d83ffd），这是引入新类型写法之前的最后一个版本。
  - DINO-WM 的权重是整个模块打包保存的，类定义要能对上。如果对不上，就跳过 G0，只和原文的数字比。

### G1 用 DINO-WM 的数据和设定训练我们的模型（标准 Wall）

- **设定**：冻结 DINOv2 patch、frameskip 5，历史帧数和学习率以 DINO-WM 权重的 `hydra.yaml` 为准。
- **门槛（事先定）**：同一套评测下，开环 CEM 和 MPC 都不低于 DINO-WM 权重（或原文数字）5 个百分点以上。达不到就先查训练，不进下一步。
- 开环 CEM 和 MPC 各 50 个 episode，种子 99，和原文一致。

### G2 WallRandom：按原文做法生成数据并训练

- **数据**：用仓库里 DINO-WM 的 DotWall 生成器，10240 条 × 50 步，墙和门的位置随机。留出一组训练里不出现的墙/门位置给测试，划分写进配置。
- **训练**：同 G1 的设定。
- **门槛**：冻结规划器在没见过的布局上，按原文评测不低于 0.82 − 5 个百分点。

### W3 WallRandom 开发集基准（只看基准，不碰方法）

- **组**：冻结规划器、AdaJEPA，各 100 个 episode，开发种子 100，布局都是没见过的。AdaJEPA 用 κ = 0 的停滞规划器跑，同时记录触发。
- **规划**：CEM 子规划器，参数同原文。按我们的闭环方式，每次执行 1 个模型步再重规划，预算 50 次，同时报 20 和 30 次。
- **停下来商量的条件**：AdaJEPA ≥ 90%，或者失败里卡住的很少，说明方法没有提升空间。

### W4 开发集上的方法（2 次运行）

- **组**：R-switch（主方法）和 R-trig（对照）。只重跑触发过的 episode，切换之前和参照逐位相同。
- **参数**：卡住触发从第 4 次开始（能算的最早一步，和迷宫一样），阈值和切换参数原样沿用，不在 Wall 上调。
- **判断标准（事先定，同 E3）**：相对 AdaJEPA，赢 − 输 ≥ 5 且 McNemar p < 0.05；同时报相对冻结规划器的结果。
- **CEM 下的验证**：停滞惩罚和本体加权都作用在规划目标上，换成 CEM 也成立，但这是第一次在 CEM 下用，冒烟测试会专门核对。

### W5 测试种子 101（只跑一次，另行确认）

冻结规划器、AdaJEPA、R-switch 各 100 个 episode。

## 3. 实现（JEPA-Stall 仓库）

1. `models/dino.py`：dinov2 固定版本（只改加载来源，不改结构）。
2. 下载：`wall_single.zip`（进行中），以及 DINO-WM 的 `outputs.zip`（G0 用）。下载的东西放在单独的目录里。数据文件先用只读张量的方式（`weights_only`）检查一遍再用。
3. `conf/plan_wall_dinowm.yaml`（复现原文评测），`conf/stag_plan_cem_wall.yaml`（我们的方法）。
4. `scripts/wall_gen.py`：生成 WallRandom 数据，包括布局划分。
5. `scripts/e3_run.py` / `e3_analyze.py`：加 `--env wall`。
6. 冒烟测试：每组 2 个 episode，核对切换前逐位相同。

## 5. 风险

1. **复现不了原文**：G0 先排除评测管线的问题，G1 再排除训练的问题，都过了才往下走。
2. **WallRandom 的生成细节原文没写全**：比如墙/门位置的范围和划分。按仓库里的生成器默认范围来，划分写清楚；G2 的门槛（0.82 − 5）会检验生成的数据是否合理。
3. **方法第一次用在 CEM 上**：触发和切换不依赖规划器，尺子修正改的是目标函数，原则上通用；冒烟测试核对实现。
4. **AdaJEPA 在 DINO 编码器上只能改预测器**：DINO 主干不更新，没有投影层可改，修模型的空间比迷宫小。W3 会看出来。
