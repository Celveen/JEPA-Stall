# 第二篇：潜空间停滞正则与神谕诊断（EVAL50 seed 100）

截至 2026-10-20。只涉及 AdaJEPA 的规划器，不含任何持续学习。代码当时在 `paper2` 分支（工作区 `worktrees/paper2/`），现已整理进 JEPA-Stall 仓库（本地 `multimodal-test/JEPA-Stall/`）。

## 0. 结论

1. **潜空间停滞正则安全，但增益小。**
   - 方法里完全没有像素、推杆这类任务相关的量。
   - 最好的一组是 SZ_mid：76.0%，AdaJEPA 是 74.9%。高 1.1 个百分点，4 胜 0 负，p=0.125。
   - 6 组都没有误伤。
2. **它确实让卡住的场景动了起来，但动的方向不对。**
   - 触发后 3 次重规划内离开卡住点的比例：SZ_hi 53%，同一批 episode 的 AdaJEPA 只有 17%，而且随强度单调上升。
   - 物体改善（6–11% 对 8%）和推杆绕到物体背后（22% 对 21%）都没有变化。
   - 赢的 4 个 episode 全是"只差推杆"的卡住，都在 K2P 救回的 10 个之内；72 个"物体没到位"的卡住一个都没解开。
3. **神谕诊断说明了原因。** 把世界模型换成真实模拟器后，"物体没到位"的卡住在剩余预算内仍然几乎解不开：
   - 用我们的潜空间目标，2/71；
   - 改用真实状态代价，还是 2/71；
   - 视野再加倍到 50 步，也只有 4/71。

   所以卡住既不是模型预测错，也不是潜空间度量的问题，而是距离型代价在有限视野内本身就有局部最优。
4. **对训练端的含义。**
   - 把动态模型训练得更准，或在训练时加"别停在原地"的正则，都解决不了这个问题。
   - 训练端唯一有希望的方向，是让潜空间距离反映"离目标还有几步"（时间距离，cost-to-go）。
   - 规划端也是同样的道理：需要一个能看到视野之外的方向来源。

## 1. 方法（全部在潜空间里定义）

**度量**：直接用规划目标函数自己的度量。

```
D(z, z') = MSE_visual(z, z') + α · MSE_proprio(z, z')    （α = 1）
d = √D
```

**触发**（只看观测）：
- 从第 11 次重规划起，计算 r = d(z_s, z_{s−3}) / d(z_s, z_goal)，即最近 3 次重规划在潜空间里走过的距离，占离目标剩余距离的比例。
- 权重 w = clip((0.15 − r) / 0.10, 0, 1)。
- w > 0 时，把当前观测记入本 episode 的记忆。记忆在整个 episode 内保留，每次重规划都用当前（已适应过的）编码器重新编码。

**惩罚**：

```
J(a) = J_task(a) + κ · P(a)
P(a) = Σ_h c_h Σ_j w_j s_j max(0, 1 − D_sp(ẑ_h, m_j) / ρ_j)²  /  Σ_h c_h
```

- ẑ_h 是计划的预测帧。c_h = 2^h 是目标函数自己的时间权重。
- 每个记忆点 m_j 的排斥区 ρ_j = β · D_sp(m_j, z_goal)，取 β = 0.25，所以排斥区永远盖不住目标。
- 强度 s_j = D(m_j, z_goal) / T，就是"停在 m_j"时的任务代价。因此停在一个满权重记忆点上，代价会变成原来的 (1+κ) 倍。

**两个版本**，区别只在排斥区用什么距离：
- **SP**：用 proprio 潜变量的距离，只看智能体在哪。
- **SZ**：用完整潜状态的距离，看整个场景。

所有参数都没有尺度依赖，换到迷宫等环境不需要改设置。

## 2. 触发的标定与离线验证

γ_hi = 0.15 是在 S7 上标定的（S7 上的 AdaJEPA 运行，280 个 episode），没有用评测集 EVAL50。标定时让它和原来的像素触发（推杆 3 次重规划净位移 < 15 px）召回率一致。

| 流 | 触发方式 | 碰到的 AdaJEPA 失败 | 碰到的本能成功的 episode |
|---|---|---:|---:|
| S7（标定） | 像素 < 15 px | 59/63 | 12/217 |
| S7（标定） | 潜空间 r < 0.15 | 59/63 | 4/217 |
| EVAL50（留出） | 像素 < 15 px | 81/88 | 25/262 |
| EVAL50（留出） | 潜空间 r < 0.15 | 83/88 | 7/262 |

**TS 式曲率**：卡住时，相邻两步潜空间速度的余弦中位数是 −0.51（S7）和 −0.57（EVAL50）；正常移动时是 +0.29 和 +0.20。卡住窗口里有 71–72% 为负，也就是在来回折返。

## 3. 设置与验证

- **模型与评测**：bias16k seed0 第 3 轮；EVAL50 seed 100（7 种形状 × 50），30 次重规划，GD 规划，AdaJEPA 更新不变。
- **对照**：AdaJEPA（escape_EVAL50/none，截到 30 次重规划）和 K2P_short2（同种子）。
- **只重跑可能被碰到的 97 个 episode**：选的是离线 r < 0.15 × 1.3 的超集。其余 253 个 episode 的正则项恒为 0，直接沿用 AdaJEPA 的结果。
- **验证**：
  - κ=0 时，4 个 episode 全部 30 次重规划的动作都与 AdaJEPA 逐位相同。
  - 在线算出的 r 与离线值相差不超过 4%。
  - 正式组里，97 个 episode 在开罚之前全部与 AdaJEPA 逐位相同。
  - 在线触发的 episode 共 90 个，与离线结果一致。

## 4. 结果（350 个配对 episode）

参照：AdaJEPA 74.9%（没见过的形状 58.0% / 见过的形状 87.5%）；K2P_short2 77.4%（60.7% / 90.0%）。

| 组 | 成功率 | 与 AdaJEPA（仅该组/仅 AdaJEPA，p） | 与 K2P_short2（p） | 没见过/见过 | 离开 | 物体改善 | 绕到背后 | 误伤 |
|---|---:|---|---|---|---:|---:|---:|---:|
| SP_lo（κ=0.5） | 75.1% | +0.3（1/0，p=1） | −2.3（2/10，p=0.039） | 58.0 / 88.0 | 22%（17%） | 9%（8%） | 21%（21%） | 0 |
| SP_mid（κ=2） | 74.9% | 0（0/0） | −2.6（1/10，p=0.012） | 58.0 / 87.5 | 24%（17%） | 8%（8%） | 21%（21%） | 0 |
| SP_hi（κ=8） | 75.1% | +0.3（1/0，p=1） | −2.3（1/9，p=0.021） | 58.0 / 88.0 | 24%（17%） | 6%（8%） | 21%（21%） | 0 |
| SZ_lo（κ=0.5） | 75.4% | +0.6（2/0，p=0.5） | −2.0（1/8，p=0.039） | 58.0 / 88.5 | 32%（17%） | 8%（8%） | 22%（21%） | 0 |
| **SZ_mid（κ=2）** | **76.0%** | **+1.1（4/0，p=0.125）** | −1.4（1/6，p=0.125） | 58.0 / 89.5 | 42%（17%） | 10%（8%） | 22%（21%） | 0 |
| SZ_hi（κ=8） | 75.7% | +0.9（3/0，p=0.25） | −1.7（1/7，p=0.070） | 58.0 / 89.0 | 53%（17%） | 11%（8%） | 22%（21%） | 0 |

括号里是 AdaJEPA 在同一批 episode、同一时刻之后的对应比例。指标定义：
- **离开**：触发后 3 次重规划内，推杆离开卡住点超过 15 px。
- **物体改善**：10 次重规划内物体误差下降超过 5 px，或者成功。
- **绕到背后**：推杆到达物体背离目标的那一侧。
- **误伤**：AdaJEPA 能成功、该组失败。

这些评价指标用了真实状态，只用于分析；方法本身只看潜变量。

**细节**
- **触发的卡住类型**：90 个触发的 episode 里，72 个"物体没到位"，18 个"只差推杆"（按触发时刻的真实状态区分）。
- **赢的 episode**：SZ 组赢的全是"只差推杆"。SZ_mid 赢了 L/1、+/3、T/6、T/7，全部在 K2P_short2 救回的 10 个之内。"物体没到位"是 0/72。没见过的形状成功率与 AdaJEPA 相同，都是 58.0%。
- **为什么 SP 组几乎无效**：proprio 版的排斥区很小，推杆稍微挪一下就躲开了。被执行计划的惩罚中位数是 0；SZ 组则是任务代价的 0.4–0.9%。
- **不拖慢**：7 个触发后才成功的 episode 一个都没丢；SZ_mid 让其中 3 个提前了 1–3 次重规划。
- **与 K2P 对比**：K2P 用了"推杆目标位置"这个任务知识，救回 10 个，其中有 3 个 I 形和 1 个 square。潜空间正则完全不用任务知识，拿回了其中 4 个。

## 5. 神谕诊断：卡住出在哪里

在 83 个 AdaJEPA 失败的卡住状态上（各自第一次触发时的真实状态），把世界模型换成真实模拟器，用 CEM 一直规划到这个 episode 的预算用完：每轮 256 个样本、迭代 5 轮，取 32 个精英，执行找到的最优计划。剩余预算中位数 16 次重规划。起点处物体误差中位 29 px、角度 13°，76% 的推杆挡在物体朝目标的一侧。

| 设定 | 解开 | 只差推杆 | 物体没到位 | 物体改善 | 推杆绕到物体背后 |
|---|---:|---:|---:|---:|---:|
| AdaJEPA（世界模型 + 潜空间目标） | 0/83 | 0/12 | 0/71 | — | — |
| O1：真实模拟器 + 潜空间目标，视野 25 步 | 9/83 | 7/12 | 2/71 | 13% | 16% |
| O2：真实模拟器 + 真实状态代价，视野 25 步 | 11/83 | 9/12 | 2/71 | 20% | 12% |
| O3：真实模拟器 + 真实状态代价，视野 50 步 | 14/83 | 10/12 | 4/71 | 29% | 23% |

真实状态代价 = 推杆与物体位置的联合误差 + 角度误差，按成功判定的标准折算（20 px 对应 20°）。时间加权与潜空间目标相同。

O1 解开的 9 个，O2 也都解开了；O2 多出的 2 个都是"只差推杆"。

**解读**：
- **物体没到位（卡住失败的 86%）**：用我们的潜空间目标（O1）和用真实代价（O2）结果一样，都只解开 2/71；视野加倍也只从 2 个变成 4 个。所以问题不在潜空间度量本身，而在任何"离目标还有多远"的距离型代价，在有限视野里都有局部最优：推杆要先绕到物体背后，这一段代价是先升后降的。这也不是世界模型预测错造成的。
- **只差推杆**：动态准确时大多能解开（O1 7/12，O2 9/12）。这正是停滞正则和 K2P 的收益来源。O2 比 O1 多解开 2 个，与之前的发现一致：潜空间目标对推杆差 20 px 左右不够敏感。
- **注意一个混杂**：O1 和 AdaJEPA 同时换了两样东西，动态（真实模拟器对世界模型）和优化器（CEM 256×5 对 GD 100 步）。所以 O1 在"只差推杆"上的收益，不能全部算到"动态更准"头上；"物体没到位"上两者都失败，这个结论不受影响。
- **对训练端的含义**：把动态训练得更准不能解决卡住，在训练里加"别停在原地"的正则也不能。训练端只有一条有希望的路：让潜空间距离反映"离目标还有几步"（时间距离），把视野之外的信息编码进去。

## 6. 下一步建议

1. **方向来源（主方法候选）**：让规划在卡住后能看到视野之外。
   - 把视野加到 50 步的作用有限，O3 只多解开 2 个。
   - 更有希望的是在潜空间学一个终端代价或时间距离（cost-to-go）：用离线轨迹训练，接在视野末端。停滞正则负责"什么时候、在哪里"，终端代价负责"往哪走"。
2. **训练端**：试时间距离类正则，即让潜空间里到目标的距离反映剩余步数，并以 temporal straightening 为对照。这是神谕诊断支持的唯一训练端方向。
3. **泛化**：同一套无量纲设置可以直接用到下面几种情况：
   - 冻结规划器；
   - 官方 AdaJEPA 权重；
   - 多布局迷宫（需要下载 diversemaze 的检查点）；
   - seed 200、300。
4. **停滞正则本身**：SZ_mid 可以作为"安全、通用"的部件保留，但单靠它不足以成为主方法。

## 7. 代码与复现

**代码**（`paper2` 分支，只新增文件，不引用持续学习模块）：
- `planning/stagnation.py`：`StagnationMPCPlanner`，继承 `EscapeMPCPlanner`，escape.mode=none。
- `scripts/stag_latent_trace.py`：重新渲染参考运行里的状态并编码，得到潜空间轨迹（位移、到目标距离、TS 余弦）。
- `scripts/stag_select.py`：在标定流上选阈值（`--calibrate`），在评测流上挑出要重跑的 episode。
- `scripts/stag_run.py`：运行各组，只在 4–7 号卡上跑。
- `scripts/stag_analyze.py`：合并结果、做配对检验、检查开罚前是否逐位一致、计算诊断指标。
- `scripts/stag_oracle.py`、`scripts/stag_oracle_summary.py`：神谕诊断。
- `scripts/stag_common.py`：模型、目标和渲染的公共函数。

**结果**：
- `eval_outputs/stag_EVAL50/<组>/<段>/`，每段包含：
  - `per_iter_logs.json`：逐次重规划的 stag_r、stag_w、stag_mem_n、stag_task、stag_pen；
  - `stag_episodes.jsonl`；
  - `stag_meta.json`。
- `eval_outputs/stag_EVAL50/oracle/O{1,2,3}.jsonl`。
- 本目录下的 `summary.md/json`、`oracle.md/json`。

**复现**：

```bash
python scripts/stag_latent_trace.py --ref eval_outputs/escape_S7/none --stream S7 --out eval_outputs/stag_S7/trace.jsonl
python scripts/stag_latent_trace.py --ref eval_outputs/escape_EVAL50/none --stream EVAL50 --out eval_outputs/stag_EVAL50/trace.jsonl
python scripts/stag_select.py --trace eval_outputs/stag_S7/trace.jsonl --calibrate
python scripts/stag_select.py
python scripts/stag_run.py --arms SP_lo SP_mid SP_hi SZ_lo SZ_mid SZ_hi --gpus 4,5,6,7 --jobs 20
python scripts/stag_analyze.py
python scripts/stag_oracle.py --variant O2 --workers 16 --out eval_outputs/stag_EVAL50/oracle/O2.jsonl
python scripts/stag_oracle_summary.py
```
